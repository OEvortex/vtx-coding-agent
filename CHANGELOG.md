# Changelog

All notable changes to Vtx are documented in this file. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed
- **A plain `pip install` can `import vtx` again** — `vtx/git/gh_app.py` imported `jwt` and `requests` at module scope, but both ship only in the `msteams` extra and neither is a core dependency. Because `tools/bash.py` imports that module for `resolve_committer_vars` at import time, `import vtx` raised `ModuleNotFoundError: No module named 'jwt'` on any install without the extra — so the published wheel could not be imported at all, and `vtx --version` could not run. `requests` is now imported optionally and `jwt` at its point of use. Every caller already fails closed without them (`resolve_committer_vars` returns `{}` when no app is configured), so an unconfigured install never needs either; one that *is* configured now gets a message naming the extra instead of an `AttributeError`. Present in 1.2.0 and 1.2.1.

## [1.2.1] - 2026-10-04

### Fixed
- **Cached tokens were never counted from a streamed response** — the chat/completions stream path yielded `chunk.usage.model_dump()`, which nests cache counts under `prompt_tokens_details`, while every consumer read the flat `cached_tokens` key. `cache_read_tokens` therefore always resolved to 0 and the context meter's `R…` segment never appeared, even when the provider was serving most of the prompt from cache. A new `_normalize_usage` flattens the payload at the one choke point, and the two duplicated normalization blocks in the non-streaming paths now route through it as well. The non-streaming and Responses paths were already correct; only streaming was affected.
- **`/model refresh` no longer dies on a single provider** — Codex returns `/models` entries with the model object nested one level down (`{"model": {...}}`), and the id extractor returned that dict verbatim, so a `.lower()` on it raised `'dict' object has no attribute 'lower'`. One malformed provider took down the refresh for all 63, leaving the user with no model list at all. Nested entries are now hoisted to the top level before parsing, which also recovers their context window and max-output limits — which had been silently dropped, so those models would have listed with `ctx=None`. Also prefers `slug` over `id`, since Codex's `id` is an opaque UUID while the slug is the name you pass to the API. Providers using OpenAI's flat shape parse exactly as before.
- **A crash during the first turn no longer loses the run** — runtime checkpoints are durable work-in-progress, but the flush gate dropped any checkpoint written before the first assistant message existed, so a crash during turn 1 discarded everything. Checkpoints now reach disk regardless.
- **A finished run is no longer resumed on reopen** — clearing a checkpoint flipped `is_active` in place, and the JSONL log is append-only, so the change was never written back. A reopened session still saw the checkpoint as active and spuriously resumed a run that had completed. Clearing now appends an inactive tombstone, and only the newest checkpoint is consulted when loading.
- **A script's own budget and an absolute deadline are no longer the same error** — `timeout_ms` was documented and reported as a wall-clock limit, so a script blocked on a tool that never returned reported `timeout` and was told to "do less work", which is the wrong remedy for a tool that never answered. Time spent waiting on a tool call is no longer charged against the script's own budget (which made `asyncio.gather` over slow tools impossible to finish), and the absolute ceiling reports as a distinct `wall_clock` kind that points at the call you were waiting on.
- **The context meter shows the pre-compaction footprint until the next message** — the info bar's counters only ever came from a turn's provider-reported usage, so anything that shrank the conversation out from under it left the bar quoting the number the conversation *had*. After a compaction the bar still reported the full pre-shrink context until the user sent another message, which is exactly when the number matters least. New `InfoBar.sync_tokens_from_session` re-derives every counter from the session log — the thing that is actually sent to the model — and both compaction paths call it: automatic compaction in `agent_runner` and `/compact` in the sessions command.
- **Inline HTML cleanup no longer eats autolinks or angle-bracket text** — the tag pattern matched any `<word ...>`, so `See <https://example.com>` rendered as `See `, `<user@host>` vanished, and ordinary prose lost `List<T>` and `a < b > c`. That traded one silent deletion for another in the same code path. Stripping is now limited to real HTML tag names, and the attribute clause requires whitespace so an email autolink survives.
- **HTML in a reply no longer renders as nothing** — rich has no handler for `html_block`, so it fell through to an unknown element and rendered empty. A model answering inside a `<div>` produced a reply with holes in it and nothing on screen to say anything was missing; `<div>hello</div>` rendered as an empty string, and a block between two paragraphs lost its contents entirely. HTML blocks are now unwrapped to their inner text.
- **`<br>` is a line break again** — inline HTML is dispatched through a different path than the block element map, so every `<br>` was silently deleted and welded the two halves of a line together: `line1<br>line2` rendered as `line1line2`. It is the most common tag in model output, so this lost one break per occurrence. Other inline tags (`<b>`, `<span>`) were leaving two to four phantom blank lines before the text.
- **A reply can mention `<br>` again** — the fix above stripped tags without knowing about inline code spans, so a tag shown in backticks was erased too and the span rendered empty. Found by writing the demo in `scripts/lol.py` and reading its own output back. Transformation now applies only to the gaps between code spans.
- **A four-backtick fence is no longer closed by its inner three-backtick one** — the streaming scanner tracked fences by "does this line start with ```" rather than by length, so a blank line inside the outer fence read as a block boundary. The stream split mid-block and rendered soft breaks collapsed (`more echo two` on one line) until finalisation corrected it. Fences now close only on a run at least as long as the one that opened them, and a line merely *beginning* with a fence while talking about fences no longer defeats the block cache.
- **Markdown tables keep their values** — markdown-it requires the delimiter row to match the header width and silently truncates body rows to it. One stray pipe degraded an entire table into raw `|---|` prose, and an extra body cell was discarded with no indication anything was lost. Widths are reconciled before parsing; extra cells fold into the last column, short rows pad, and column alignment is preserved.
- **A codemode script's return value keeps its newlines** — the returned value was unconditionally `json.dumps`'d, so a script returning prose came back as a single escaped line (`"line one\nline two"`), the information destroyed before anything reached the renderer. Strings now pass through unchanged; every non-string value renders exactly as before.
- **A horizontal rule is visible** — `markdown.hr` used `colors.border` at **1.55:1** contrast against the background, effectively invisible, and fainter than the table rule beside it at 4.12:1, which inverted the visual hierarchy. Now `colors.muted` at 6.15:1.

### Added
- **`TreeSelector` and `InfoBar` widgets** — the session tree gained a real widget rather than ad-hoc drawing, with node selection, movement and filtering, plus `FlatNode`/`GutterInfo` to carry per-row state. `InfoBar` centralises the status line's contextual readouts — file changes (with a `FileChangesModal` for per-file detail), token usage and agent status — and the running indicator now carries a spinner and rotating status lines instead of a static string.

### Changed
- **UI modules moved to `vtx.tui`, and the `vtx.coding_agent.tui` namespace is gone** — the coding-agent namespace had become a pass-through for every UI module, so importing `vtx.tui.app` and `vtx.coding_agent.tui.app` gave two paths to one module and two chances to import half of it. Everything now lives under `vtx.tui`, `vtx.coding_agent.cli` is the only remaining member of that namespace, and the prompt editor's pieces were consolidated into a single `vtx/tui/input.py`. Tests assert both that no references to the old namespace survive and that every public name in `vtx.tui` resolves.

### Removed
- **The dead `tui2` package** — 922 lines holding a second copy of the prompt editor under a namespace nothing imported. Its `InputBox` was a near-duplicate of the live one in `vtx/tui/input.py`, which is still what the queue, chat and session surfaces use, so the risk was not deletion but a future edit landing in the copy nobody runs. (`InputBox` itself is unchanged; the commit that dropped this was titled for the component, which is misleading in isolation.)

## [1.2.0] - 2026-10-03

### Added
- **An `/effort` panel, and `/thinking` kept** — the thinking picker was a bare list of bare names, so there was no way to tell `high` (more reasoning, slower) from `max` (most reasoning, slowest) without leaving the app for external docs. Every level now carries a description from one `THINKING_LEVEL_DESCRIPTIONS` map, laid out on the settings panel's column width so the descriptions align. The context line names the model, how many levels it offers, and **why a level is missing**: a new `_thinking_availability` cross-checks the model's catalog `thinking_level_map` against what is actually offered, which surfaces the exact-model-id requirement in place. That last one matters because `get_model` matches exactly — `space-bunny-alpha` misses the catalog entry `stealth/space-bunny-alpha`, falls back to the provider's raw effort enum, and silently offered `none` for a model whose map marks it unsupported. The panel now says `catalog entry not found, check the exact model id` rather than presenting a widened list as authoritative. `/effort` is a routable alias; `ctrl+t` still cycles. It is deliberately *not* advertised in autocomplete: `/settings` is the discoverable entry point for these sub-commands.
- **MCP tools are reachable from a `codemode` script** — an MCP server's tools were registered as ordinary tool calls and invisible to every script, which is backwards: code mode is the mechanism that makes a large MCP tool set affordable, so the tools a server publishes should arrive there. A connected server can offer more tools than fit in a prompt, and the previous arrangement could only either declare all of them or leave them out. A script's tool set is now the session's live tool list rather than the global registry, rebuilt when the set's identity changes rather than when something remembers to invalidate it, so a server that connects, disconnects, or gains a tool mid-session is reflected instead of leaving `UnknownTool` from inside a working script.
- **An exposure taxonomy for MCP tools** — `exposure` and `tool_exposure` in `mcp.json`, per server or per tool (exact names and `*` patterns). `direct` declares a tool to the model as an ordinary call; `codemode` makes it reachable from a script and lists it in the codemode catalog instead; `codemode-deferred` and `deferred` are reachable but unlisted, findable by `tools.search` or `tool_search`; `hidden` is unreachable from all three. `codemode` is the default, because a hundred tools the model must call one at a time is a hundred turns, while a hundred it composes in a script is a handful. An exact name beats a pattern, and among patterns the first declared wins — documented, because `{"*": ..., "delete_*": ...}` resolves deletes by the `*` and a user who means the opposite has to know that. See [docs/mcp.md](docs/mcp.md).
- **A non-`direct` MCP tool is no longer declared to the model** — the exposure taxonomy was only half-wired: a `codemode` tool was correctly kept out of the *codemode catalog* while still being sent to the provider as an ordinary tool definition, so a two-hundred-tool server still cost two-hundred definitions per turn and the setting saved nothing. `ConversationRuntime.declared_tools()` is now the single place that decides what the model is offered, and it honours exposure: only `direct` (and built-ins, which have no exposure) reach the request. A `hidden` tool is dropped from the session's tool list entirely rather than filtered by each consumer, so a future code path cannot reach one by forgetting to check.
- **A `direct` MCP tool is still callable from a script** — declared directly *and* composable is not a conflict. A model needing six of a server's tools in one turn should not have to pay six; it is only left out of the codemode catalog, since the model already has it in front of it.
- **`tool_search` can no longer promote a denied tool** — activation widened its lookup to every *registered* tool rather than the session's, so a tool an agent profile had denied by name could be pulled back into the active set by asking for it in prose. The model describing a capability was enough to un-deny it. The pool a search draws from is already the live set, so a match is now by construction something the session is allowed to have.
- **A malformed `output_schema` degrades instead of raising** — an MCP tool's schema arrives from a third party, unvalidated, and it is rendered into a declaration on every turn. A server declaring `output_schema: "oops"` raised out of the renderer, which would have taken down every request in the session rather than that one tool's description. Non-mapping schemas are now answered with `Any`, and a `structuredContent` field of the wrong shape renders the bare `CallToolResult` rather than an invented inner type.
- **`tool_exposure` wildcard keys are accepted by the config parser** — `{"delete_*": "hidden"}`, the one setting that makes a broad server usable with care, was rejected as a malformed key because the validator only allowed bare tool names. The entire pattern-resolution machinery was unreachable through the front door.
- **A script receives an MCP tool's whole result, not its rendering** — results are flattened to text and truncated to 20 KB for a model, which is right there and wrong for a script: filtering a large structured value in code is the entire reason to write one. `ToolResult.structured` carries the value across when it differs from the rendered text, and an MCP tool's crosses as the whole `CallToolResult` — `content` blocks verbatim, `structuredContent`, `isError` — with `_meta` stripped, since it is server plumbing that carries cursors and rate-limit state. A tool's declared output schema is spelled into the declaration as `CallToolResult<...>`, so the model knows to index in rather than parse a string; a shared types preamble is printed only when something actually returns one. An `isError` result resolves rather than raising, because a server that fails usually says why in its result and a script that can read that and branch is doing something useful.
- **Tools inside a script are governed like the model's own** — a script called `tool.execute` directly, skipping `beforeToolCall`/`afterToolCall`, the permission gate, and the TUI's records, so one approved `codemode` call could do anything any exposed tool could with no second look. Nested calls now emit the same extension hooks, honor the same argument rewriting, and answer to the same permission decision. The case that matters: the gate answers *allow* or *prompt*, and **prompt is a refusal inside a script**, because a script has nobody to ask — the model is told to call that tool directly so the user can approve it. A script is a way to do the ungated calls together, not a way to get a gated one done unseen. A gate that throws refuses rather than defaulting to allow. `governed_invoker` is the wrapper for a host that wires its own pipeline.
- **`image()` in the sandbox** — a tool returning a screenshot had it flattened to text before a script saw it, so there was no way to pass one on. `image()` takes a base64 data URI, an `{"image_url": ...}` object, or an image block straight out of an MCP result, and it becomes real image content in the tool result. Remote `http` URLs are refused: a script that could point the transcript at any host the model chose would be an exfiltration primitive rather than a feature.
- **Deadlock detection was added, and does not currently fire** — the sandbox has exactly two ways to resume a blocked script, a tool reply arriving or a timer firing, so a script blocked with neither pending is not slow but dead. `Limits.detect_stalls` defaults to `True` and the `stalled` kind, `ScriptStalled`, and its remedy text all exist. The guard does not fire, though: `_StallGuard.watch` treats only the script task and its own watcher as its own, but `_run_script` is itself awaited by `runner`, which is always live and never in that set — so the no-other-live-tasks condition is never satisfied and the watch loop always continues. Verified by execution: a script awaiting `asyncio.Event().wait()`, or `asyncio.sleep(60)`, reports `timeout` after the full deadline rather than `stalled` in a millisecond. **Recorded as known-dead rather than described as a feature**, because the whole point of the diagnostic was that a misdiagnosed deadlock sends the model off splitting work that was never going to finish. The fix is small — include the calling task in the exclusion set — but it is a behaviour change to the sandbox and belongs in its own commit.
- **Enforced budgets for a script: `max_tool_calls`, `max_output_tokens`, `memory_limit_bytes`** — previously only `timeout_ms` existed, and the docs said so. A call budget is charged at *admission* rather than completion, because four calls already in flight have already been paid for and checking at the end would let a script exceed the ceiling by exactly its own concurrency. An over-budget call is refused as a catchable `ToolError` rather than truncated, so the script can stop and adapt. Output is cut in the middle with head and tail kept and the cut reported, since a silently shortened result reads as a complete one. Memory is an `RLIMIT_AS` inside the worker — a runaway allocation was otherwise only stopped by the deadline, so the user watched it climb for all thirty seconds. All three are also settable per script via `# @options`, and all three clamp: a script may ask for less than the host allows, never more.
- **`# @options` gained `max_tool_calls` and `max_output_tokens`, and now actually clamps** — the tool path passed a script's `timeout_ms` straight through as a *replacement* rather than a clamped value, so a script could widen the host's deadline up to the parser's ceiling. All three fields resolve min-wins against the host's limit.
- **`tool_search`, for finding a tool that exists but was not offered** — the in-sandbox `tools.search` answers "can a script reach this"; this answers "can the model call this", by activating a match so the tool is declared on the next request. Same BM25 ranker, indexing schema property names and their descriptions, so a query naming a field finds the tool that has it; every match carries the signature, so finding and calling are one step. Without the activation it would tell the model about a tool it still cannot call, and the next attempt would fail as an unknown name — worse than staying quiet.
- **A namespaced catalog, budgeted fairly across namespaces** — the budget was a single global cheapest-first pass, so with two hundred MCP tools on one server and a dozen built-ins the cheap ones took the budget and a second server's tools were left out entirely with no sign they existed. Selection is now round-robin across namespaces, cheapest-first within each turn, so every namespace is represented before any namespace is complete and an empty one prints `none shown` rather than vanishing. An MCP server's own `instructions` becomes its section header, so a server's self-description of its tools reaches the model and costs nothing when no script is written.
- **Nested calls are observable** — `ToolCall` carries a duration, the success summary names the tools it called, and a failure summary names the ones that failed and how many calls already happened. A script that half-ran usually already had real side effects, and "Script failed (script)" alone left no way to know whether the half that ran changed anything.

- **A confined code-mode sandbox for model-written scripts** — the model writes one small Python program that calls only the tools you inject, instead of paying one round trip per operation. **A script runs as ordinary Python, and that is deliberate.** An earlier draft of this entry described three confinement layers (`sys.addaudithook`, a stripped `__builtins__`, an import allowlist); none of them are in the code now, and an entry claiming otherwise would be worse than no entry. There is exactly one boundary: **a process per execution**, so a deadline is a `kill` rather than a request and `while True:` dies with everything else. A script has full builtins, the full standard library, installed packages, filesystem, subprocesses and network, running with the user's own privileges — verified by execution, not assumed. This follows `ref/prime-agent`: a coding agent driving the developer's own interpreter, where restricting the interpreter buys less than it costs in model capability. What a script cannot reach is the host's *live state* — the running agent, the session, the TUI, and every tool — because that lives in the other process. **A script is therefore as trusted as the user running it; it is an isolation boundary for the host, not a security sandbox against the model.** Treat exposure as the control that matters here: `codemode` makes a tool reachable from a script, `hidden` makes it unreachable, and the permission gate covers what a script calls. Failures carry nine kinds so the model recovers accurately instead of treating everything as "the script broke", and the four tool-level ones are raised as distinct exception classes a script can `except` by name — `UnknownTool` means fix the name, `ToolFailure` means change your approach. Store writes are staged and committed only on success, so a half-run script leaves no state behind. `adapt_tools()` wires it to the built-in tool surface, bridging the one real mismatch: `ToolResult.result` is a string while the sandbox boundary is JSON data, so a JSON-parseable result reaches the script as structured data and a prose one reaches it as text. Launch costs ~140ms because the worker is launched by file path rather than with `-m`, which would import the agent SDK first. See [docs/codemode.md](docs/codemode.md).
- **A `codemode` tool that composes the others** — registered in the tool registry, so the model reaches a confined script the way it reaches any other tool. Where every other tool is one operation, this is an interpreter: the model writes a Python script that calls the other tools, so N operations cost one turn and the filtering and aggregation between them happen in code instead of in the model's context. Default-on, because a tool the model has to be told about before it uses it is a tool it will not think to use. Its description carries the live tool catalog, so the model can write the script in the same turn it learns what the script can call; it excludes itself from that catalog, because a script that could start a script would nest without limit. Marked mutating, so the permission gate covers what a script does rather than just that it ran, and the approval preview shows the script itself, since that is the whole of what it will do. See [docs/codemode.md](docs/codemode.md).
- **A `tools.search` discovery step inside the sandbox** — the catalog is capped by a token budget, so a large tool set is a subset, and a model reading a subset would conclude the missing capabilities do not exist. `tools.search(query=..., limit=..., offset=...)` ranks the full set (BM25 over names, descriptions, and schema property descriptions) and returns each match with the signature that calls it, so finding a tool and knowing how to use it are one round trip. An exact path is a lookup rather than a keyword match, and an empty query browses alphabetically. Always injected — so recovery advice that says "search for it" is followable — but advertised only when the list is genuinely partial.
- **A pinned `Agents` panel for sub-agent fan-out** — sub-agents were visible only as the tool block for the dispatch that launched them, so a background run froze at `0 turns · 0 tool calls` and a dozen other agents worked invisibly. A standing strip above the editor now lists every sub-agent in flight at once, one row each, with its name, description, turn/tool/token counters, elapsed time, and a live sub-line for what it is doing right now; the info bar carries the `N running, M queued agents` summary, and the strip retires itself (after a short linger, so a final row is readable) when nothing is in flight. The registry that feeds it keys runs by tool-call id instead of sub-agent name, so four concurrent `Explore` agents are four rows rather than one smeared row. Queued agents get a count line rather than rows of their own — they are waiting, and rows of "queued" would crowd out the ones actually working. The goal beacon renders the same rows from the same registry, so the two views cannot disagree.
- **Real sub-agent concurrency cap (`task.max_concurrent`)** — a model that dispatched a dozen sub-agents in one turn opened a dozen provider streams at once: slower, thrashy, and with nothing honest to report but a wall of spinners. A FIFO admission queue now bounds how many run at once (default 4, `0` = uncapped) and a dispatch waits for its slot *before* it builds a session or a provider, so "running" and "queued" are real counts rather than decoration. Slots are reserved at hand-off, so a fresh arrival cannot barge past a queued one; a cancelled waiter passes its slot along instead of stranding it. A config reload resizes the live queue, draining waiters when the cap is raised and never pre-empting a run in flight when it is lowered.
- **`/reload` hot reloads the running session** — edit an extension, agent, skill, or `config.yml`, run `/reload`, and keep the conversation. An explicit command rather than a file watcher, because a watcher has to guess whether a write has finished and reloads on every editor autosave, while a command fires once, when the code is ready, at a bounded and visible cost. The order is the safety property — extensions get a `session_shutdown` with `reason="reload"` to release sockets and caches before anything is swapped, config is reloaded before discovery so extensions and agents resolve against the new paths, and the active agent, model, provider, thinking level, and conversation all survive; only what the agent is *made of* is replaced. The report names what actually changed (`+probe, -web_search`, `skills +2`) rather than just claiming success. Refuses to run mid-turn, since swapping the tool set and event bus under a live agent loop would leave the in-flight turn holding tools the next turn will not advertise.
- **`/reload` also applies settings, so a `config.yml` edit takes effect** — reloading the file is not the same as applying it. **Themes** apply live — `get_styles()` reads `config.ui.colors`, which `UIConfig` derives from the theme, so the stylesheet is rebuilt and `refresh_css()` re-parses it; `/themes` had been claiming a restart was needed, which was inaccurate. The reload reports each setting it pushed (`theme -> ayu`, `permissions -> auto`) instead of only reporting resource counts, and skips an unchanged theme so a reload does not rebuild the stylesheet and flicker the UI. Everything else in the config is read at the moment it is used — the tool-result budget, the compaction threshold, `max_turns`, `colored_tool_badge`, `thinking_lines` — so re-reading the file is already sufficient, and `reload_config()` mirrors the harness knobs on its own. (An earlier draft of this entry also covered a `mode:` switch; the RLM mode it switched between has since been removed — see Removed.)
- **`/undo` and `/redo` with content-addressed working-tree snapshots** — turn-level rewind that puts the conversation *and* the files back in sync. Each turn is bracketed by two shadow-git captures, and the changed-path list is a worktree diff between them rather than a list of paths some tool reported, so edits made through `bash`, `ipython` or any other non-reporting tool are captured alongside `edit`/`write`. Reverting maps every changed path to the tree at the start of the earliest affected turn. Snapshots live in a repository under `~/.vtx/snapshots/<hash>/`, entirely separate from the project's own history: no commits, no branches, no `refs/stash` entries, and the project's `.gitignore` is honoured so `node_modules`/`.venv` are never hashed. Blobs over 2 MiB are dropped from the index so one stray artifact cannot stall every later turn. Undo stages the rewind and leaves it reversible until you send your next prompt; redo walks forward and clears at the newest turn. Rewind is non-destructive — it moves the session leaf rather than deleting entries, so an undone turn stays reachable.
- **Tree jumps restore files too** — `/tree` previously re-pointed the session leaf and left the working tree untouched, so picking an old point showed a past conversation over a dirty worktree. Selection now runs through the same revert path as `/undo` and restores the worktree to match; only the choice of boundary differs, with `/tree` jumping to any point and `/undo` stepping one turn at a time. Any entry maps to the turn that contains it, so selecting a tool call or a compaction still lands on a boundary the restore understands.
- **Session-scoped goal ownership** — goals were a per-project pool, so two vtx instances working the same repository fought over focus and could mutate each other's goals. A `GoalService` is now bound to one session, and a goal created by session A is invisible to every other instance. Goals left behind by a session that has exited are announced at startup and can be taken over with `goal(action="claim")`; goals whose owner still holds a liveness lease are never offered.
- **Sub-agent visibility during goal runs** — a goal run's dispatched sub-agents were visible only inside their own chat blocks, so there was no way to tell what else was working on the objective. A registry fed from the same `task`-tool event stream now backs a live `Agents` row in the goal beacon and a per-sub-agent breakdown in the expanded dashboard, showing outcome, turn and token counts, and a tool breakdown.
- **Live compaction block** — summarization is no longer an opaque wait. A real block reports elapsed time, the token delta, and a section checklist that ticks as each heading arrives in the stream, with the finished summary expandable inline. The InfoBar gained a hand-built context gauge with a tick at the auto-compaction threshold that stays put once the fill passes it.

- **MCP client, and any MCP server's tools alongside the built-in ones** — servers declared in `mcp.json` (the shape Claude Desktop, Cursor, and other agents already read, so an existing config copies over unchanged) are connected at session start, and each server's tools are registered through the ordinary tool path: the same registry, the same permission gate, the same tool blocks, the same interrupt. A tool annotated `readOnlyHint` skips the approval prompt, which is the whole reason servers annotate tools at all. Config lives in `~/.vtx/mcp.json` and, for trusted projects only, `<project>/.vtx/mcp.json` — a project server is a command vtx would execute, so one sitting in a repository the user merely opened is not run. `/mcp` lists every server with its state and tool count and can reload, reconnect, enable, or disable one; `/reload` picks up `mcp.json` edits too. See [docs/mcp.md](docs/mcp.md).
- **A dependency-free MCP client at `vtx.mcp`** — a transport-neutral core over stdio, Streamable HTTP, and in-memory transports. The client owns request correlation, the `initialize` handshake, timeouts, cancellation, and the paginated list helpers; a transport owns only framing and I/O. Cancellation is the `asyncio.Event` that `BaseTool.execute` already takes, so `Esc` during an MCP tool call follows the same path as every other tool. Protocol version `2025-11-25`, accepting servers that negotiate back as far as `2024-11-05`. Deliberately *not* in scope, matching the reference client this is modelled on: batched JSON-RPC, the legacy HTTP+SSE transport, acting as a server, sampling, and tasks.
- **A large MCP result becomes a pointer, not a wall of text** — model-facing text is capped at 20 KB, keeping the head and the tail with the middle elided, and the full output is written to a mode-0600 temp file whose path the model is handed. A third-party tool can return anything, and the session-level tool-result budget is 200 KB, which is far too generous to be the only limit on content vtx did not write. Binary resources are spilled the same way; images become real image content rather than a file path, because a model can see one and cannot read a path.
- **Server shutdown cannot orphan a process group** — closing follows the MCP spec (close stdin, wait, `SIGTERM`, then `SIGKILL`) and signals the whole process group, so a server launched through a wrapper like `npx` or `uvx` does not leave grandchildren holding the pipe open. Covered by a fixture that ignores both stdin EOF and `SIGTERM` and spawns a child of its own; the test asserts the grandchild is gone, not merely that `close()` returned.
- **OAuth sign-in for remote MCP servers** — a server that answered `401` used to be a dead end: it reported `needs-auth` and contributed nothing, with no way to fix it from inside vtx. `/mcp signin <name>` now runs the full authorization-code flow with PKCE: protected-resource and authorization-server discovery, dynamic client registration, a loopback redirect listener, the code exchange, and token storage in a mode-0600 `~/.vtx/mcp-auth.json`. The browser is opened *and* the URL printed, because a browser is a convenience while the terminal is the channel you can definitely read — which is what makes a headless run recoverable. After that the transport sends the bearer token itself and refreshes transparently on a `401`, preferring a refresh token over another round trip through a browser. Two `401`s arriving together share one refresh, and a request whose token was already replaced is retried rather than refreshed again, since with rotating refresh tokens the second attempt would fail *and* discard the new grant. Credentials are keyed by server URL, so one server's token can never be sent to another. Credentials are never sent to a non-HTTPS endpoint (bar a loopback redirect), and an issuer that does not match the one requested is fatal rather than worked around, because sending a client secret to whatever answered would be wrong either way. A server that returns `401` but whose authorization metadata cannot be found still reports `needs-auth` rather than `failed` — signing in is still the right next step, and the underlying reason is kept on the status for `/mcp` to show.
- **Project MCP files can be trusted, and the decision says what it runs** — `<project>/.vtx/mcp.json` was honoured by a hardcoded `False`, so a project server could never start and a checked-in config looked like it had no effect. `/mcp trust` needs two presses: the first lists every server the file defines and the exact command each would run, the second grants trust. A prompt that does not name the commands is not a decision anyone can make, and this one means "run these". The decision is stored per resolved project path in `~/.vtx/trusted-projects.json` and applies to later sessions in that project only. Nothing grants it implicitly — not on first use, not because a file is small, and not from anything inside the project directory, so a repository cannot trust itself. `/mcp untrust` revokes it, `/mcp` reports an untrusted project file rather than passing over it in silence, and an unreadable store fails closed: every project reads as untrusted.
- **MCP resources are reachable by the model** — the client could list and read resources, but nothing exposed them to the agent, so a server publishing a database schema or a set of files was invisible. Three session-level tools close that: `list_mcp_resources`, `list_mcp_resource_templates`, and `read_mcp_resource`. They are session-level rather than per-server because the names are the ones models already know from other coding agents and because three tools cost the same however many servers are connected. Each takes a `server` argument, listing with one returns a single page plus a cursor and without one walks every page of every server, reporting a server that failed under `errors` rather than hiding the ones that worked. MCP App user interfaces (`ui://` URIs, `profile=mcp-app` HTML) are filtered out, since they are pages for a host to render rather than content for a model. Reading produces text and images a model can use and spills a binary resource to a private file. They appear only when a server is actually connected — three tools that can only ever return an empty list are noise, and a session whose only server is broken is exactly the case that would leave them permanently dead.
- **`/mcp` command, and failures that name themselves** — one report listing every server with its state and tool count, because "MCP did not work" is not an actionable message. A slow or broken server reports itself once at startup and never blocks a session: startup waits up to 10 seconds for all servers in parallel, then proceeds, and a straggler contributes its tools when it lands.

### Changed
- **The codebase is ten focused packages, mirroring the reference monorepo** — the harness was nested at `vtx.ai.agent`, so `vtx.ai` was a 116-module grab bag holding the entire runtime beside the LLM layer, and "the AI package" meant anything and everything. The harness is now a sibling at `vtx.agent` and `vtx.ai` holds only AI code (116 → 29 modules). Two packages were added as genuine leaves that import nothing from `vtx` at all, the property that makes the layering checkable rather than aspirational: `vtx.protocol` (the message/stream types, the tool and provider contracts, error formatting) and `vtx.telemetry` (spans, processors, the console and JSONL exporters). Two more were split out by concern: `vtx.codemode`, the confined script sandbox, which is imported one-way by the harness and no longer buried inside it; and `vtx.git`, the `gh` CLI wrapper, GitHub App auth, and branch metadata, which had no business in a foundation package. Dependency direction is now `protocol`/`telemetry` → `core`, `git`, `ai` → `agent` → `coding_agent`, with `tui` and `mcp` above — and every remaining upward edge is function-local, so no module-level cycle exists. The layering the reference enforces and this one now matches.
- **The Textual UI is a base toolkit plus a product UI** — `vtx.tui` was one flat package holding reusable primitives and the coding agent's screens, so the base layer carried the product's concern for agent, model, session, goal, and slash-command state. `vtx.tui` is now the base toolkit (input editing and completion, fuzzy matching, overlay lists, LaTeX and formatting helpers, clipboard, styling, the block renderers for tool calls and results); `vtx.coding_agent.tui` is the product (app shell, chat pane, panels, dialogs, slash commands). The base package never imports the product, which is not cosmetic: the harness already depends on `vtx.tui` for `TaskToolBlock` and tool-output truncation, so a base→product edge would have had the harness importing the product it is supposed to sit under. Three modules moved the *other* way after their actual dependencies were checked rather than their names — `task_ui` is pure rich-text formatting with no widget at all, and `autocomplete` and `ask_user` are the completion machinery and dialog that `input` and `blocks` consume.
- **One module path per concern** — the codebase had grown a layer of re-export shims: 34 modules across `vtx.coding_agent` that did nothing but `from vtx.<other>.… import (…)` and set `__all__`, plus *three* module paths for the package version (`vtx.ai.agent.version`, `vtx.core.version`, `vtx.coding_agent.version`). Two names for one concern means two places to look, two places to edit, and a shim that silently keeps a stale symbol alive after the thing it re-exports changes. Every duplicate now has a single home and callers point directly at it; no compatibility shims remain. The alias that did survive is deliberate: the one documented seam a sub-agent runner needs is an explicit `set_subagent_runner()` hook.
- **The goal dashboard and the `Agents` panel are now one grammar** — the goal beacon above the editor and the `Agents` strip directly below it were two unrelated widgets: the beacon hung its rows off a `▌` rail behind a shaded ` vtx-goal ` chip, while the panel hung its rows off a `│ ├─` tree behind a `● Agents` header. Different left edge, different header, different label weight, and a `▌ │ ├─` double edge where the two met. The row vocabulary — one `● Header`, one `│ ├─` tree, bold labels, dim activity, muted counters — now lives in one place and both strips are built from it, so moving your eye between them is moving within one panel. The frame went with it: a `╭─╮` box spends two rows and two very loud rules saying "this is a panel", and said it *loudest* on a wide terminal, where the horizontal rules are longest and the content they enclose is no wider than it would be without them. One fact now occupies one row — status, objective and accounting share the header line, and the `Current` row was deleted because it only restated the `▸` the task list already showed. Colour carries state rather than decoration: pending tasks are muted instead of the warning orange that made a running plan look like a wall of alerts, and the mark sits in its own column so the one column worth scanning can be read straight down. Subtasks hang off their parent with the continuation bars *before* the branch (`│ │ ├─ · t2.1`), which is what they are, rather than after it where the row read as a sibling with a stray bar trailing it. The progress bar is a slim half-cell-rounded `━` over a hairline track instead of `█`/`░`, so it creeps rather than stuttering in 8% jumps, and it is omitted entirely when there is no plan yet rather than charting `0/0`. Long-form text is still never clipped: the verification contract wraps, and the activity ledger drops the repeated date that put six identical `2026-09-27` prefixes in a column wide enough to hold the message.
- **`Ctrl+Shift+G` is a real toggle again** — the action was named `toggle_goal_dashboard` but only ever *posted* the expanded dashboard to the chat log, which has no inverse: a second press appended an identical copy of the same forty-line block, nothing could take either of them back, and the log filled with the same dashboard until it scrolled away. So the one affordance labelled "expand" had no collapse. The expanded view is now a `ModalScreen` overlay — open, close, open again, with the conversation left exactly as it was — dismissed by `Esc` or the same chord, and re-rendering on a timer rather than showing the snapshot it was opened with, because a goal is a live thing and a frozen dashboard looks authoritative without being so. A goal archived while the overlay is up now says so instead of leaving a stale render, and the app is back to one dashboard per press no matter how many you give it.
- **Witty status lines are suppressed while a sub-agent fan-out is in flight** — the `Agents` panel is already the standing view of the fan-out: it names every running sub-agent, what it is doing right now, and its turns, tokens and duration. The random quip printed above it said the same thing less precisely, and because the two rotate on independent timers they visibly contradicted each other, with the line reading "asking the user" while the row directly beneath it read `grep`. The status line keeps its spinner and its `esc to interrupt` hint, which are facts, and drops the quip, which is not. An explicitly supplied message (`Creating handoff…`) still shows, so a caller that chose to state a fact is never silenced, and the quip returns when the fan-out lands rather than having been burned on a rotation nobody saw.
- **One live line per sub-agent, instead of a row plus a sub-line** — a running agent took two lines: a task row, then a separate continuation for what it was doing, so a five-agent fan-out spent ten lines on five facts and the thing you actually watch — what the agent is doing *now* — was pushed below the fold. Everything moved onto the row, and the row now cycles through all three phases in place: a tool call while one is in flight (`grep · searching…`), the response streaming in once the model starts writing, and `thinking…` before either. The streaming text is **left**-truncated rather than right, because the characters that just arrived are the ones being read; right-truncating a growing response shows you the start of a sentence you already scrolled past. The label is the dispatch's task ("Rate codebase quality") rather than the agent profile's blurb, which for the default sub-agent was the same boilerplate on every row; the agent name became a dim tag and disappears for the default sub-agent, where it identifies nothing. Counters share a fixed column across the panel so the token figures line up, and are dropped whole when the terminal is narrow — tool count, then tokens, keeping the duration, since "is it stuck?" is the question a watcher actually has. A run over a minute prints `2m15s` rather than `135.1s`, and finished runs collapse to one `✓ 2 finished · 4.1k tokens` line so the strip shrinks as work lands.
- **Sub-agent presets are gone** — `task.subagent_presets` gave the `task` tool a second way to define a sub-agent, `.vtx/agent/<name>.py` being the first, with a precedence order between them: agent file, then preset, then `general-purpose`. That made a name's meaning depend on files you may not have — `Explore` was a read-only agent if a matching file existed and a read-only preset if it didn't, with nothing on screen to say which — and each preset was a second copy of the same `AgentDef` fields in a different container with its own migration path. The tool description also advertised the three preset names to the model, so it reached for `Explore`/`Plan` where a project's own agent file would have been the better pick. `subagent_type` is now resolved against the loaded agents alone; an unknown or empty name runs the default sub-agent (parent tool surface, 200-turn budget), and the parameter defaults to empty rather than `"general-purpose"`, a string that was only ever meaningful as a preset name. Config version 15 drops the preset block on load, so an existing config cannot suggest a knob that no longer exists, and the `SubagentPreset` schema class is no longer re-exported from `vtx.coding_agent.config`.
- **The `task` tool block in chat is now just a dispatch receipt** — it re-rendered a spinner on an 80ms timer plus live turn/tool counters for every dispatch, so a fan-out buried the conversation under a dozen identical spinners restating what the panel already showed, and a background dispatch finished as a finished-looking `✓` block reading `0 turns · 0 tool calls`. The block now shows what was dispatched and how it ended on one or two lines (`▸ Explore  Map public API surface` + `⎿ Running in background (ID: …)`), stays a receipt while the sub-agent is still running instead of freezing a zeroed summary, repaints only on a progress event rather than on a timer, and keeps `ctrl+]` for the transcript. A late failure in a background sub-agent now reads as an error rather than as the success the launch already reported.
- **Thinking levels are now derived per model from the catalog** — the picker and the `ctrl+t` cycle read a models.dev `reasoning_options` list that said gpt-5.6 accepts `max`, while the provider carried a hand-maintained enum that had drifted and stopped at `xhigh`, and `set_thinking_level` raised a raw `ValueError` on the disagreement. `resolve_thinking_levels` in `vtx.ai.thinking` is now the single source of truth for every selector (picker, cycle, `/thinking`, session restore) and only offers a level when we know it can be sent: catalog-verified tiers, narrowed to what the transport's effort enum can express and to what the transport's wire format has a spelling for. Consequences: `gpt-5-pro` correctly offers only `high` (the catalog says reasoning cannot be turned off); a model the catalog describes only as reasoning-capable offers `default` — no reasoning parameter at all — rather than a guessed effort that might be rejected; and a level the current model doesn't support is clamped to the nearest supported one instead of failing, so switching models or restoring a session can't break a request. Models that publish a *token budget* rather than named efforts (Claude Haiku/Sonnet 4.5) now get a budget ladder sent as `thinking.budget_tokens` instead of being dropped to no thinking at all. The provider enums are derived from one shared vocabulary rather than three copied lists, and `off`/`none` are no longer two spellings that can drift apart — the clamp used to mis-resolve any `none` level.
- **Compaction preserves far more detail** — the summarization prompt never asked for length or for concrete artifacts, so an 800k-token session collapsed to a ~2k-token summary and the next agent effectively restarted from scratch. It now opens with binding length and fidelity rules (use the whole output budget, scale with session size, never replace an artifact with a description of it, enumerate rather than merge) and mandates twelve sections that capture what the old seven missed: all user messages verbatim, environment and runtime facts, interface contracts and key code, decisions and rejected alternatives, problems with their root causes, per-file created/edited/read state, commands run and their outcomes, the exact in-progress state, next actions, and an explicit "do not redo" list of completed work and dead ends. The handoff is written in a single pass — an earlier draft-then-write `<analysis>`/`<summary>` scratchpad was dropped, since every token it emitted was a token the next agent had to read for a document that was then thrown away. Summarization also runs with `thinking_level="off"` so reasoning tokens are not billed against the context being reclaimed. Applies to both automatic and `/compact` runs, and to `compact.run(instructions=...)` focus hints.
- **Goal beacon is width-aware** — the above-editor beacon hardcoded a 52-character objective and did its layout arithmetic in characters rather than terminal cells, so it sheared on CJK and emoji and never matched the real widget width. Every width is now measured in cells and laid out to the widget's actual width (recomputed on resize), degrading to a single status line on narrow terminals. The verification contract wraps instead of being clipped, and long token counts scale to `M` so a long goal no longer reads `27631.9K`.
- **Skill slash commands are now opt-in, as documented** — `register_cmd` defaulted to `true` while `AGENTS.md` and `docs/skills.md` both describe it as opt-in, so every discovered skill was injected into the `/` list. The installed skill set went from 56 entries in the command list to the 9 that actually ask to be there; all 56 remain available to the agent as context, and any skill is still reachable explicitly via `/skill:<name>`.
- **Compaction falls back to a token estimate** — when the provider reported no usage, auto-compaction had nothing to compare against the context window and simply never fired. The agent and runtime now estimate conversation size from total characters, so a provider that under-reports usage can still trigger compaction.

### Fixed
- **Markdown headings and tables render as something** — every heading level from `#` to `######` was the same `bold` style, so a reply mixing them gave the model no visible structure to read, and tables came out of rich's default renderer wrapped in padded blank lines with an indented, unstyled rule — two tables in one reply read as separate paragraphs. Headings now ramp through the existing palette (`title` → `accent` → `markdown_heading` → `muted` → `dim`) with weight kept at every level, so the hierarchy still reads on a monochrome terminal where colour is unavailable. Tables drop the edge lines and style the header and rule from the theme. Blockquotes, list markers, and rules had no theme entry at all and were falling back to the terminal default.
- **An exact model search ranked by accident** — the fuzzy matcher's exact-match bonus required the query to equal the whole searched string, which is `"{model id} {provider}"` in the picker, so it could never fire: all twelve `claude-opus-5*` ids scored an identical 412.2 and the winner was whichever the sort happened to keep. The root cause was worse than the dead bonus — greedy subsequence walking anchors on the first occurrence of each character, so `claude-opus-5` inside `anthropic/claude-opus-5` began at the "c" of *anthropic* and never reached the real run, misplacing every boundary bonus. A contiguous run is now tried first (nearly every typed query is contiguous) and the subsequence walk is the fallback, so the exact id scores 512.2 against 412.2 for its `-batch` variant, and a namespaced exact match 499.2 against 399.2. The contiguous fast path is also one C-level find instead of a Python walk, which dropped filtering the 6361-entry catalog from 8.6 ms to 5.5 ms per keystroke.
- **`ctrl+t` said nothing useful when it could not cycle** — a model with a single effort level (any non-reasoning model, or one whose catalog advertises no control) cannot cycle, so the action reported `Thinking level: none`, which reads like a successful state report and is byte-identical on every press. The code's own comment says a silent no-op is indistinguishable from a dead key; the fix made the no-op speak without saying it *was* a no-op. It now reports `Thinking level is fixed at none for this model, nothing to cycle`, or names the model when there is no level list at all.
- **The goal dashboard's left edge was a dashed line of disconnected ticks** — the block's border was drawn only on content rows, so the blank rows between sections carried nothing and the edge read as a column of loose marks running the height of a forty-line post: a rendering artefact rather than a container delimiting anything. The border is now drawn on the separators too, which is what every box-drawing panel has always done. Two related defects fell out of the same investigation. The beacon carried both `padding: 0 1` and `margin: 0 1`, so its rail sat one cell right of every chat block above it and the two read as one broken edge; and every dashboard row was padded out to the terminal edge, so a twelve-character line shipped a ~1400-cell run of styled spaces after it — pure overhead, and a hazard for terminal selection and soft-wrap. The overlay's rows are now their natural width, while the pinned beacon keeps the exact-width invariant its layout tests assert.
- **A paused or blocked goal advertised work that was not happening** — the `▸ current` mark came from `current_task()`, which reports the next pending task regardless of goal status, so a goal paused with `Esc` showed a bold accent "current" row for a task nobody was working on, and a blocked goal looked identical to a running one. Nothing is in flight unless the goal is `active`, so nothing is marked. Separately, the *reason* a goal was blocked or paused lived only in the goal file and the tool snapshot, so a blocked goal and a paused one were indistinguishable on screen; the dashboard now carries a `why` line in the user's own words.
- **The goal beacon froze a live fan-out** — the widget repainted on a fixed five-second interval, so while the very sub-agents it was summarising streamed, thought and switched tools, the row reporting them sat mid-tool for seconds at a time and the beacon could contradict the panel directly below it. The cadence is now half a second while anything is queued or running and five seconds otherwise.
- **The narrow-terminal goal status line overflowed the screen** — the one-line fallback appended a fixed set of segments and only guarded the objective, so a running goal with a plan printed a 37-cell line into a 24-cell terminal and the terminal wrapped it onto a second row under the editor. Cells are now budgeted rather than assumed: the objective gets a reservation first, then each segment is taken in priority order if it still fits, and a segment that does not fit is *skipped* rather than ending the line, so a long token count can no longer hide the short progress figure standing behind it.
- **Queued sub-agents got a row each in the dashboard, and every row was identical** — an agent that has not started can only report `0 turns · 0 tokens · 0.0s`, and two identically-named queued runs rendered as indistinguishable lines, so the list was noise that read as information. Queued agents now collapse to one `○ N queued` line, matching the pinned panel, and finished runs summarise to `✓ N finished · 12.4k`. The same edit removed a whitespace-only row that appeared when nothing had finished: indenting the summary produced `"  "`, which is truthy, so the renderer appended a blank line the beacon then drew as a second gap.
- **The goal beacon reported a plan the reader could misread** — the task window was anchored on the last *completed* task, which could scroll the one row that matters — the active task — off the bottom, and the subtasks of the task in flight were appended after the window instead of hanging off their parent, stranding them under whichever task happened to be last. The window is now centred on the active task, so the one row that cannot be reconstructed from a `+N more` count is always on screen, and subtasks ride with whichever task owns the current focus.
- **The recap ate the sub-agent's result** — a recap is a summary of a *finished* conversation, but the idle timer only checked whether the parent turn was running. A session that had handed its work off to background sub-agents looked idle, so thirty seconds later it spent an LLM call restating what was already on screen, and the summary landed in the chat *instead of* the sub-agent's result reaching the agent. The finding was then visible to the user and invisible to the model — which reads as "the sub-agent finished and the notification never arrived", when the notification had worked all along. Recap is now gated on the session being genuinely idle: sub-agents queued or running suppress it, checked at all three points where it can slip through (arming the timer, the timer firing, and after the LLM call is already in flight). It is deferred rather than dropped, so it returns once the work lands, and an explicit `/recap` still works mid-fan-out because there the user asked for it.
- **A cancelled or failed turn could leave the session permanently "busy"** — `_run_agent` cleared `_is_running` on the normal path only, so a run that raised — or was cancelled when a newer prompt took over the worker group — left the flag set. Every gate in the app reads that one flag: Esc, the status line, the recap timer, and every background wake-up, all of which would have refused to fire for the rest of the session. The flag is now cleared in a `finally`.
- **A finished background sub-agent never reached the agent** — `background: true` dispatched work that took minutes, and the parent turn took seconds, so the sub-agent almost always finished *after* its parent had gone idle. Two gaps in a row swallowed the result: the parent loop only drained completions *between* turns, so an already-settled task was appended to the session but not shown to the model until the turn after next; and nothing started that turn, because a completion had no way to signal an idle session. The sub-agent ran, produced an answer, and the agent then replied as if it had never happened — the failure mode is silence, not an error, so it read as the model ignoring work it had requested. `BackgroundTaskManager` now exposes a settlement listener, the TUI resumes the session on it (with a status line naming the sub-agent, so the turn is not mysterious), and `Agent.run` injects anything already settled *before its first model call* rather than between turns. A completion is still delivered exactly once, and a wake-up turn that dispatches again is capped at four chained resumes before the session stops and says why — a fan-out has to converge.
- **A finished sub-agent row stayed pinned for the rest of the session** — the Agents panel stopped its repaint timer as soon as nothing was running, so the linger window that decides when the strip retires was never re-checked. The last finished row sat above the editor indefinitely, which is the opposite of what a live-status strip should do. The panel now keeps a slow clock alive through the linger window and unpins itself when it closes, verified by a test that fails against the old stop-on-idle behaviour.
- **Sending a message erased every tracked sub-agent** — the sub-agent registry was cleared at the start of each run, on the reasoning that rows should describe the work in flight *now* rather than every sub-agent the session ever dispatched. That is wrong for exactly the sub-agents that matter: a `background: true` dispatch returns immediately and finishes on a later turn, so the user's next message made the panel blink out from under agents still working toward it, and their counters restarted from nothing. The turn boundary now ages out only runs that *ended* more than three minutes ago, so a live or queued agent is never dropped however old its dispatch.
- **A reloaded extension could silently run the previous version** — the extension loader handed each file to `spec.loader.exec_module`, which validates cached bytecode against the source's *mtime and size*. An edit that kept the file the same length — changing a constant, a threshold, a version string — was served from `__pycache__`, so a reload reported success while executing the old code. The same applied a fortiori to a package extension's submodules, which resolve through the normal finder and stayed stale across every reload until the process restarted. The loader now compiles the source it just read, and a reload additionally drops the imported modules and each package's `__pycache__`, so an edited, added, or renamed submodule is actually visible. A failed import also removes the half-built module, so a later reload cannot bind to a broken one.
- **`ctrl+t` could kill the app on a supported thinking level** — cycling to a level the catalog advertised but the provider's stale enum did not list raised `ValueError: Invalid thinking level 'max' for openai. Valid levels: ['none', 'minimal', 'low', 'medium', 'high', 'xhigh']` straight out of the Textual action, tearing down the running session (recoverable only via `vtx -r <id>`). Two independent lists decided what was valid — the models.dev-derived picker levels and the provider's own enum — and nothing reconciled them; the provider now shares one enum that includes `max`, `set_thinking_level` clamps instead of raising, and the runtime clamps against the offered set before applying, so no stale or restored value can reach an exception.
- **Auditor verdicts were truncated mid-sentence, causing endless re-audit loops** — the completion auditor's findings were clipped to 1500 characters on write, so a verdict was stored ending at e.g. `**Contract status:** 106 goal-re…`. The executing agent could not read the rest, could not tell the text had been clipped, re-completed the goal, and was failed again on the same finding indefinitely. Verdicts and completion claims are now stored whole; where text must still be shortened for the activity ledger it is cut on a paragraph or word boundary and explicitly marked as clipped. `goal(action="get")` likewise returns the full objective, verification contract and verdict instead of a 200-character summary, so the agent's only view of its own state is no longer silently abridged.
- **`Session.load` discarded every `runtime_checkpoint` entry** — the loader had no branch for that entry type, so a resumed session dropped them silently and every parent chain running through a turn was severed, collapsing `get_branch()` to a handful of entries and breaking `/tree` history for any reloaded session.
- **Undo restored nothing when a turn's edits came from an unreporting tool** — the restore set was derived from `file_changes` on tool results, so edits made through `bash`, `ipython` or a `python` cell were excluded and the UI reported "no file changes" over a still-dirty worktree. The restore set is now the worktree diff recorded when the turn is bracketed.
- **Undo never matched any file in real sessions** — tool results report absolute paths while git tree entries are project-relative, so the two sets could never intersect and every restore was a silent no-op. Both sides are normalized against the project root before comparison.
- **Undo could not see a turn's snapshot** — the worktree is hashed at turn start but the user message is appended from inside the agent loop, so the snapshot always precedes the prompt it belongs to; the lookup scanned the other way and found nothing. Turn records now name the user message they belong to, so association no longer depends on entry order.
- **YAML folded block scalars mangled skill descriptions** — frontmatter was parsed with a naive key/value scan, so `description: >` was stored as the literal string `>`, destroying the description of 15 bundled skills in both the model-facing skill index and the `/` list. Frontmatter now parses with `yaml.safe_load`, falling back to the old scan.
- **TUI freeze on chatty tool output** — live tool output re-rendered and re-laid-out once per output delta, so a tool streaming faster than the frame rate saturated Textual's single event loop and the whole app stopped responding, with keystrokes, the spinner and `Esc` all blocked. Renders and scroll-to-bottom now coalesce into one pass per frame, matching the batching the text-streaming path already used; 2000 deltas dropped from ~860ms to ~150ms of event-loop time.

- **The `skill` tool ran a stale fork of the skills loader** — `vtx.coding_agent.context.skills` had diverged into a second, hand-maintained copy with no Python-skill detection, no YAML frontmatter parsing, and `register_cmd` still defaulting to `True`. The tool therefore advertised a different set of skills than the system prompt it is supposed to mirror, and two earlier fixes (opt-in registration, folded-scalar descriptions) never reached it. It is now an alias of the single canonical implementation; the rest of that package was already byte-identical.
- **An optional tool parameter that was explicitly `null` raised a validation error the model could not see or recover from** — the JSON-Schema bridge typed a non-required field as `str` with `default=None`, so passing `null` for an unset optional was rejected even though omitting it was fine. Models routinely send `null` for an unset optional, and with MCP every schema arrives from a third-party server, which turned this from a rare edge into the common case. Non-required fields are now nullable.

### Removed
- **Built-in agent profiles** — `plan` (a read-only formulation profile) was hardcoded in the loader, so every session carried an agent the user never asked for, and changing what the agent could be meant editing the shipped list rather than writing a file. Profiles now come only from `.vtx/agent/<name>.py` and `~/.vtx/agent/<name>.py`; out of the box the registry is empty, `shift+tab` cycles a single "no profile" entry, and the runtime takes the session-default path it already took when no agent was active.
- **The `task` tool, renamed to `delegate_subagent`** — not removed. `task` collided with the goal system's task list, so a model told to "check the task" could reasonably mean the todo list or the dispatcher. Same behaviour, a name that says which one it is. Also removes the back door through `tools_deny`: `delegate_subagent` can call `bash`, so a profile that denies `bash` while allowing it has not restricted anything.
- **The RLM mode and its persistent IPython kernel** — the `rlm` mode (later `code_first`) collapsed the tool surface to a single `ipython` tool backed by a long-lived kernel, which is the one design the codebase could not confine: it had ambient filesystem, network, and subprocess authority by construction, because a persistent interpreter *is* that authority. It is replaced by the code-mode sandbox, which gives the model the same "compose calls in code" affordance with none of the reach. Removed: the `rlm` mode and its config field, the `code_first` rename, `IpythonManager`/`IpythonRuntime`/`IpythonKernel` and their kernel pool, the `ipython` tool, the host tool-call RPC bridge, the continual-harness refinement subsystem (`refine`, `harness.py`, auto-refine turn gate, `/refine`, `/harness`, and the refinement TUI rendering), four bundled python skills (`agent-message`, `agent-observe`, `compact`, `refine`), and the `refine` config block. About 25,000 lines.
- **The last bundled python skill (`edit`)** — a python skill is API documentation for a module the persistent kernel imported; with the kernel gone, its `SKILL.md` describes calls nothing can make. Removing it means Vtx ships no python skills at all. Skills that *are* instructions are unaffected; python skills are simply hidden from every discovery surface, because an advertised one spends context on a dead end.
- **The `mode` and `refine` config keys, rather than keeping them inert** — an earlier pass kept both fields so an existing `config.yml` would validate. Migration handles that instead: v14 drops `mode`, v16 drops `refine`, and both rewrite the file so a stale knob cannot sit in a config reading as a live one. A file already stamped at the current version is unaffected — pydantic ignores unknown keys, so a stray `mode:` still loads and does nothing.
- **`HarnessStateEntry` stays, inert** — nothing writes it, but it is part of the session-file schema. Removing a union member would make every session recorded before this release unloadable, which is a worse outcome than carrying a few dead lines.
- **The `/refine` and `/harness` slash commands** — removed with the refinement subsystem, and also dropped from the in-app `/help` list, which had kept advertising them.
- **Deprecated OpenJarvis utility modules** — `progress_events`, `prompt_templates`, `restart`, `runtime`, `searchusage` and `tool_hints` were unreferenced and are deleted along with the obsolete realtime-streaming test that covered them; `.gitignore` and the TUI stylesheet lost their corresponding dead entries.

## [1.1.0] - 2026-08-26

### Added
- **Clipboard image paste** — `ctrl+v` pastes images from the system clipboard into the input as `[image #N]` placeholders (up to 5 per message); queued and steer messages carry their attached images through editing and replay.
- **Image-aware submissions** — images are ordered before text in user messages for better grounding, text is optional for image-only submissions, and the welcome-screen shortcut list documents `ctrl+v`.
- **`vtx.core.bytes_util`** — shared byte-size formatting/parsing helpers (`format_bytes`, `parse_bytes`) with dedicated tests.
- **Persistent goal system (`vtx-goal`)** — durable, file-backed objectives for long-running work, ported from the pi-goal-x workflow. `/goal [seed]` and `/sisyphus [seed]` run a guided draft (clarify → propose → confirm) while `/goal-direct` / `/sisyphus-direct` create immediately; goals live as editable markdown under `.vtx/goals/` with an append-only activity ledger and survive across sessions (session-scoped focus via `/goal-focus`, multiple open goals per project). The agent drives everything through a single action-based `goal` tool (`create | get | update | set_tasks | update_task`) with id-stable parent-linked task trees and per-task verification contracts. An above-editor status beacon shows live progress (status · elapsed/tokens · task window · current task · contract · file), `Ctrl+Shift+G` posts the expanded dashboard, auto-continue checkpoint turns keep the agent working toward an active goal until it genuinely finishes — pressing `Esc` pauses — and completion runs an independent auditor sub-agent that inspects the workspace before archiving (`<approved/>` archives; changes-required feedback stays attached). Manage with `/goal-list`, `/goal-status [verbose|health]`, `/goal-unfocus`, `/goal-tweak`, `/goal-pause`, `/goal-resume`, `/goal-clear`, `/goal-cancel`, and `/goal-settings`. See [docs/goals.md](docs/goals.md).
- **Idle session recap** — after an agent run finishes and you stay idle (`recap.idle_seconds`, default 30s), or when you resume a session, vtx drafts a 1–3 sentence "where you left off" summary using the current model and renders it in the chat log; typing clears it. New `/recap` slash command drafts one on demand, and `recap.enabled: false` opts out.
- **OpenAI Responses API adapter & unified reasoning resolution** — new Responses transport adapter with unified reasoning-effort resolution; the Responses transport is now routed through the official `openai` SDK.
- **Extended-thinking parity and token tracking** — per-model reasoning-effort detection from models.dev drives thinking levels on any verified provider, with stream cleanup and usage-tracking parity across transports.
- **Interactive UI primitives for extensions (`ctx.ui`)** — handlers declared as `(event, payload, ctx)` now receive a full context whose `ctx.ui` exposes interactive dialogs: `await ctx.ui.confirm()`, `await ctx.ui.select()`, `await ctx.ui.input()` (real modal dialogs backed by the Textual TUI, safe no-op defaults in headless mode), `ctx.ui.notify()` rendered in the chat log, and `ctx.ui.setStatus()` / `ctx.ui.setWidget()` for a persistent footer bar. All dialogs support `timeout` and abort-`signal` kwargs.
- **`await ctx.ui.custom(component)`** — show arbitrary Textual widgets or `ModalScreen`s modally from an extension and await the dismissed result.
- **Provider request hooks** — new `before_provider_headers` and `before_provider_request` extension events fire once per outgoing LLM request across all transports (OpenAI SDK, Anthropic HTTP). Handlers can inject/override/delete HTTP headers and inspect or fully replace the wire payload; later handlers chain off earlier replacements; retries reuse prepared values without re-firing handlers. Backed by a transport-level registry (`vtx.ai.provider_hooks`) bridged onto the extension bus automatically.

- **`/update` command** — check for and install the latest vtx release from inside the TUI.
