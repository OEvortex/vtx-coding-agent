# Changelog

All notable changes to Vtx are documented in this file. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **A pinned `Agents` panel for sub-agent fan-out** — sub-agents were visible only as the tool block for the dispatch that launched them, so a background run froze at `0 turns · 0 tool calls` and a dozen other agents worked invisibly. A standing strip above the editor now lists every sub-agent in flight at once, one row each, with its name, description, turn/tool/token counters, elapsed time, and a live sub-line for what it is doing right now; the info bar carries the `N running, M queued agents` summary, and the strip retires itself (after a short linger, so a final row is readable) when nothing is in flight. The registry that feeds it keys runs by tool-call id instead of sub-agent name, so four concurrent `Explore` agents are four rows rather than one smeared row. Queued agents get a count line rather than rows of their own — they are waiting, and rows of "queued" would crowd out the ones actually working. The goal beacon renders the same rows from the same registry, so the two views cannot disagree.
- **Real sub-agent concurrency cap (`task.max_concurrent`)** — a model that dispatched a dozen sub-agents in one turn opened a dozen provider streams at once: slower, thrashy, and with nothing honest to report but a wall of spinners. A FIFO admission queue now bounds how many run at once (default 4, `0` = uncapped) and a dispatch waits for its slot *before* it builds a session or a provider, so "running" and "queued" are real counts rather than decoration. Slots are reserved at hand-off, so a fresh arrival cannot barge past a queued one; a cancelled waiter passes its slot along instead of stranding it. A config reload resizes the live queue, draining waiters when the cap is raised and never pre-empting a run in flight when it is lowered.
- **`/reload` hot reloads the running session** — edit an extension, agent, skill, or `config.yml`, run `/reload`, and keep the conversation. Modelled on pi-mono's `AgentSession.reload()`: an explicit command rather than a file watcher, because a watcher has to guess whether a write has finished and reloads on every editor autosave, while a command fires once, when the code is ready, at a bounded and visible cost. The order is the safety property — extensions get a `session_shutdown` with `reason="reload"` to release sockets and caches before anything is swapped, config is reloaded before discovery so extensions and agents resolve against the new paths, and the active agent, model, provider, thinking level, and conversation all survive; only what the agent is *made of* is replaced. The report names what actually changed (`+probe, -web_search`, `skills +2`, `mode tool_first -> code_first`) rather than just claiming success. Refuses to run mid-turn, since swapping the tool set and event bus under a live agent loop would leave the in-flight turn holding tools the next turn will not advertise.
- **`/reload` also applies settings, so a `config.yml` edit takes effect** — reloading the file is not the same as applying it, and the two settings that matter most were previously restart-only. **`mode:`** now switches the live agent over: editing `mode: code_first` and reloading collapses the tool surface to the persistent REPL, and switching back restores the surgical set, with the system prompt rebuilt to match so the model is never told about a surface it does not have. The collapse policy moved out of the two places that inlined it into one runtime method, because a mode switch has to be able to run it mid-session rather than only at construction. **Themes** apply live too — `get_styles()` reads `config.ui.colors`, which `UIConfig` derives from the theme, so the stylesheet is rebuilt and `refresh_css()` re-parses it; `/themes` had been claiming a restart was needed, which was inaccurate. The reload reports each setting it pushed (`theme -> ayu`, `permissions -> auto`) instead of only reporting resource counts, and skips an unchanged theme so a reload does not rebuild the stylesheet and flicker the UI. Everything else in the config is read at the moment it is used — the tool-result budget, the compaction threshold, `max_turns`, `colored_tool_badge`, `thinking_lines` — so re-reading the file is already sufficient, and `reload_config()` mirrors the harness knobs on its own.
- **`/undo` and `/redo` with content-addressed working-tree snapshots** — turn-level rewind that puts the conversation *and* the files back in sync. Each turn is bracketed by two shadow-git captures, and the changed-path list is a worktree diff between them rather than a list of paths some tool reported, so edits made through `bash`, `ipython` or any other non-reporting tool are captured alongside `edit`/`write`. Reverting maps every changed path to the tree at the start of the earliest affected turn. Snapshots live in a repository under `~/.vtx/snapshots/<hash>/`, entirely separate from the project's own history: no commits, no branches, no `refs/stash` entries, and the project's `.gitignore` is honoured so `node_modules`/`.venv` are never hashed. Blobs over 2 MiB are dropped from the index so one stray artifact cannot stall every later turn. Undo stages the rewind and leaves it reversible until you send your next prompt; redo walks forward and clears at the newest turn. Rewind is non-destructive — it moves the session leaf rather than deleting entries, so an undone turn stays reachable.
- **Tree jumps restore files too** — `/tree` previously re-pointed the session leaf and left the working tree untouched, so picking an old point showed a past conversation over a dirty worktree. Selection now runs through the same revert path as `/undo` and restores the worktree to match; only the choice of boundary differs, with `/tree` jumping to any point and `/undo` stepping one turn at a time. Any entry maps to the turn that contains it, so selecting a tool call or a compaction still lands on a boundary the restore understands.
- **Session-scoped goal ownership** — goals were a per-project pool, so two vtx instances working the same repository fought over focus and could mutate each other's goals. A `GoalService` is now bound to one session, and a goal created by session A is invisible to every other instance. Goals left behind by a session that has exited are announced at startup and can be taken over with `goal(action="claim")`; goals whose owner still holds a liveness lease are never offered.
- **Sub-agent visibility during goal runs** — a goal run's dispatched sub-agents were visible only inside their own chat blocks, so there was no way to tell what else was working on the objective. A registry fed from the same `task`-tool event stream now backs a live `Agents` row in the goal beacon and a per-sub-agent breakdown in the expanded dashboard, showing outcome, turn and token counts, and a tool breakdown.
- **Live compaction block** — summarization is no longer an opaque wait. A real block reports elapsed time, the token delta, and a section checklist that ticks as each heading arrives in the stream, with the finished summary expandable inline. The InfoBar gained a hand-built context gauge with a tick at the auto-compaction threshold that stays put once the fill passes it.

- **MCP client, and any MCP server's tools alongside the built-in ones** — servers declared in `mcp.json` (the shape Claude Desktop, Cursor, and other agents already read, so an existing config copies over unchanged) are connected at session start, and each server's tools are registered through the ordinary tool path: the same registry, the same permission gate, the same tool blocks, the same interrupt. A tool annotated `readOnlyHint` skips the approval prompt, which is the whole reason servers annotate tools at all. Config lives in `~/.vtx/mcp.json` and, for trusted projects only, `<project>/.vtx/mcp.json` — a project server is a command vtx would execute, so one sitting in a repository the user merely opened is not run. `/mcp` lists every server with its state and tool count and can reload, reconnect, enable, or disable one; `/reload` picks up `mcp.json` edits too. See [docs/mcp.md](docs/mcp.md).
- **A dependency-free MCP client at `vtx.mcp`** — a transport-neutral core over stdio, Streamable HTTP, and in-memory transports. The client owns request correlation, the `initialize` handshake, timeouts, cancellation, and the paginated list helpers; a transport owns only framing and I/O. Cancellation is the `asyncio.Event` that `BaseTool.execute` already takes, so `Esc` during an MCP tool call follows the same path as every other tool. Protocol version `2025-11-25`, accepting servers that negotiate back as far as `2024-11-05`. Deliberately *not* in scope, matching the reference client this is modelled on: batched JSON-RPC, the legacy HTTP+SSE transport, acting as a server, sampling, and tasks.
- **A large MCP result becomes a pointer, not a wall of text** — model-facing text is capped at 20 KB, keeping the head and the tail with the middle elided, and the full output is written to a mode-0600 temp file whose path the model is handed. A third-party tool can return anything, and the session-level tool-result budget is 200 KB, which is far too generous to be the only limit on content vtx did not write. Binary resources are spilled the same way; images become real image content rather than a file path, because a model can see one and cannot read a path.
- **Server shutdown cannot orphan a process group** — closing follows the MCP spec (close stdin, wait, `SIGTERM`, then `SIGKILL`) and signals the whole process group, so a server launched through a wrapper like `npx` or `uvx` does not leave grandchildren holding the pipe open. Covered by a fixture that ignores both stdin EOF and `SIGTERM` and spawns a child of its own; the test asserts the grandchild is gone, not merely that `close()` returned.
- **`/mcp` command, and failures that name themselves** — one report listing every server with its state and tool count, because "MCP did not work" is not an actionable message. A slow or broken server reports itself once at startup and never blocks a session: startup waits up to 10 seconds for all servers in parallel, then proceeds, and a straggler contributes its tools when it lands.

### Changed
- **The goal dashboard and the `Agents` panel are now one grammar** — the goal beacon above the editor and the `Agents` strip directly below it were two unrelated widgets: the beacon hung its rows off a `▌` rail behind a shaded ` vtx-goal ` chip, while the panel hung its rows off a `│ ├─` tree behind a `● Agents` header. Different left edge, different header, different label weight, and a `▌ │ ├─` double edge where the two met. The row vocabulary — one `● Header`, one `│ ├─` tree, bold labels, dim activity, muted counters — now lives in one place and both strips are built from it, so moving your eye between them is moving within one panel. The frame went with it: a `╭─╮` box spends two rows and two very loud rules saying "this is a panel", and said it *loudest* on a wide terminal, where the horizontal rules are longest and the content they enclose is no wider than it would be without them. One fact now occupies one row — status, objective and accounting share the header line, and the `Current` row was deleted because it only restated the `▸` the task list already showed. Colour carries state rather than decoration: pending tasks are muted instead of the warning orange that made a running plan look like a wall of alerts, and the mark sits in its own column so the one column worth scanning can be read straight down. Subtasks hang off their parent with the continuation bars *before* the branch (`│ │ ├─ · t2.1`), which is what they are, rather than after it where the row read as a sibling with a stray bar trailing it. The progress bar is a slim half-cell-rounded `━` over a hairline track instead of `█`/`░`, so it creeps rather than stuttering in 8% jumps, and it is omitted entirely when there is no plan yet rather than charting `0/0`. Long-form text is still never clipped: the verification contract wraps, and the activity ledger drops the repeated date that put six identical `2026-09-27` prefixes in a column wide enough to hold the message.
- **`Ctrl+Shift+G` is a real toggle again** — the action was named `toggle_goal_dashboard` but only ever *posted* the expanded dashboard to the chat log, which has no inverse: a second press appended an identical copy of the same forty-line block, nothing could take either of them back, and the log filled with the same dashboard until it scrolled away. So the one affordance labelled "expand" had no collapse. The expanded view is now a `ModalScreen` overlay — open, close, open again, with the conversation left exactly as it was — dismissed by `Esc` or the same chord, and re-rendering on a timer rather than showing the snapshot it was opened with, because a goal is a live thing and a frozen dashboard looks authoritative without being so. A goal archived while the overlay is up now says so instead of leaving a stale render, and the app is back to one dashboard per press no matter how many you give it.
- **Witty status lines are suppressed while a sub-agent fan-out is in flight** — the `Agents` panel is already the standing view of the fan-out: it names every running sub-agent, what it is doing right now, and its turns, tokens and duration. The random quip printed above it said the same thing less precisely, and because the two rotate on independent timers they visibly contradicted each other, with the line reading "asking the user" while the row directly beneath it read `grep`. The status line keeps its spinner and its `esc to interrupt` hint, which are facts, and drops the quip, which is not. An explicitly supplied message (`Creating handoff…`) still shows, so a caller that chose to state a fact is never silenced, and the quip returns when the fan-out lands rather than having been burned on a rotation nobody saw.
- **One live line per sub-agent, instead of a row plus a sub-line** — a running agent took two lines: a task row, then a separate continuation for what it was doing, so a five-agent fan-out spent ten lines on five facts and the thing you actually watch — what the agent is doing *now* — was pushed below the fold. Everything moved onto the row, and the row now cycles through all three phases in place: a tool call while one is in flight (`grep · searching…`), the response streaming in once the model starts writing, and `thinking…` before either. The streaming text is **left**-truncated rather than right, because the characters that just arrived are the ones being read; right-truncating a growing response shows you the start of a sentence you already scrolled past. The label is the dispatch's task ("Rate codebase quality") rather than the agent profile's blurb, which for the default sub-agent was the same boilerplate on every row; the agent name became a dim tag and disappears for the default sub-agent, where it identifies nothing. Counters share a fixed column across the panel so the token figures line up, and are dropped whole when the terminal is narrow — tool count, then tokens, keeping the duration, since "is it stuck?" is the question a watcher actually has. A run over a minute prints `2m15s` rather than `135.1s`, and finished runs collapse to one `✓ 2 finished · 4.1k tokens` line so the strip shrinks as work lands.
- **Sub-agent presets are gone** — `task.subagent_presets` gave the `task` tool a second way to define a sub-agent, `.vtx/agent/<name>.py` being the first, with a precedence order between them: agent file, then preset, then `general-purpose`. That made a name's meaning depend on files you may not have — `Explore` was a read-only agent if a matching file existed and a read-only preset if it didn't, with nothing on screen to say which — and each preset was a second copy of the same `AgentDef` fields in a different container with its own migration path. The tool description also advertised the three preset names to the model, so it reached for `Explore`/`Plan` where a project's own agent file would have been the better pick. `subagent_type` is now resolved against the loaded agents alone; an unknown or empty name runs the default sub-agent (parent tool surface, 200-turn budget), and the parameter defaults to empty rather than `"general-purpose"`, a string that was only ever meaningful as a preset name. Config version 15 drops the preset block on load, so an existing config cannot suggest a knob that no longer exists, and the `SubagentPreset` schema class is no longer re-exported from `vtx.coding_agent.config`.
- **The `task` tool block in chat is now just a dispatch receipt** — it re-rendered a spinner on an 80ms timer plus live turn/tool counters for every dispatch, so a fan-out buried the conversation under a dozen identical spinners restating what the panel already showed, and a background dispatch finished as a finished-looking `✓` block reading `0 turns · 0 tool calls`. The block now shows what was dispatched and how it ended on one or two lines (`▸ Explore  Map public API surface` + `⎿ Running in background (ID: …)`), stays a receipt while the sub-agent is still running instead of freezing a zeroed summary, repaints only on a progress event rather than on a timer, and keeps `ctrl+]` for the transcript. A late failure in a background sub-agent now reads as an error rather than as the success the launch already reported.
- **`rlm` mode is now `code_first`** — the mode was named after its implementation (recursive language model) rather than the capability it gives the model, which made it read as an internal detail sitting next to the user-facing `tool_first`. `code_first` describes the contract: the model writes code, the host supplies tools. Config version 14 migrates `"rlm"` to `"code_first"` on load, so existing configs keep their mode and the rewrite is visible on disk. The `vtx.ai.agent.rlm` package and the model-facing `import rlm` namespace are unchanged, so the kernel protocol and existing sessions are untouched.
- **Thinking levels are now derived per model from the catalog, the way opencode derives its variants** — the picker and the `ctrl+t` cycle read a models.dev `reasoning_options` list that said gpt-5.6 accepts `max`, while the provider carried a hand-maintained enum that had drifted and stopped at `xhigh`, and `set_thinking_level` raised a raw `ValueError` on the disagreement. `resolve_thinking_levels` in `vtx.ai.thinking` is now the single source of truth for every selector (picker, cycle, `/thinking`, session restore) and only offers a level when we know it can be sent: catalog-verified tiers, narrowed to what the transport's effort enum can express and to what the transport's wire format has a spelling for. Consequences: `gpt-5-pro` correctly offers only `high` (the catalog says reasoning cannot be turned off); a model the catalog describes only as reasoning-capable offers `default` — no reasoning parameter at all — rather than a guessed effort that might be rejected; and a level the current model doesn't support is clamped to the nearest supported one instead of failing, so switching models or restoring a session can't break a request. Models that publish a *token budget* rather than named efforts (Claude Haiku/Sonnet 4.5) now get a budget ladder sent as `thinking.budget_tokens` instead of being dropped to no thinking at all. The provider enums are derived from one shared vocabulary rather than three copied lists, and `off`/`none` are no longer two spellings that can drift apart — the clamp used to mis-resolve any `none` level.
- **Compaction preserves far more detail** — the summarization prompt never asked for length or for concrete artifacts, so an 800k-token session collapsed to a ~2k-token summary and the next agent effectively restarted from scratch. It now opens with binding length and fidelity rules (use the whole output budget, scale with session size, never replace an artifact with a description of it, enumerate rather than merge) and mandates twelve sections that capture what the old seven missed: all user messages verbatim, environment and runtime facts, interface contracts and key code, decisions and rejected alternatives, problems with their root causes, per-file created/edited/read state, commands run and their outcomes, the exact in-progress state, next actions, and an explicit "do not redo" list of completed work and dead ends. The handoff is written in a single pass — an earlier draft-then-write `<analysis>`/`<summary>` scratchpad was dropped, since every token it emitted was a token the next agent had to read for a document that was then thrown away. Summarization also runs with `thinking_level="off"` so reasoning tokens are not billed against the context being reclaimed. Applies to both automatic and `/compact` runs, and to `compact.run(instructions=...)` focus hints.
- **Goal beacon is width-aware** — the above-editor beacon hardcoded a 52-character objective and did its layout arithmetic in characters rather than terminal cells, so it sheared on CJK and emoji and never matched the real widget width. Every width is now measured in cells and laid out to the widget's actual width (recomputed on resize), degrading to a single status line on narrow terminals. The verification contract wraps instead of being clipped, and long token counts scale to `M` so a long goal no longer reads `27631.9K`.
- **Skill slash commands are now opt-in, as documented** — `register_cmd` defaulted to `true` while `AGENTS.md` and `docs/skills.md` both describe it as opt-in, so every discovered skill was injected into the `/` list. The installed skill set went from 56 entries in the command list to the 9 that actually ask to be there; all 56 remain available to the agent as context, and any skill is still reachable explicitly via `/skill:<name>`.
- **Compaction falls back to a token estimate** — when the provider reported no usage, auto-compaction had nothing to compare against the context window and simply never fired. The agent and runtime now estimate conversation size from total characters, so a provider that under-reports usage can still trigger compaction.
- **RLM background shell and a consolidated REPL prompt** — long-running shell commands started from a cell no longer block the kernel, and the RLM prompt set was folded into a single source after the standalone master prompt was retired.
- **IPython block modernized** — RLM cell output moved to Textual-native rendering with `textual.highlight` syntax highlighting and is aligned to the base `ToolBlock` layout, so expand/collapse and output visibility behave the same as every other tool.

### Fixed
- **The goal dashboard's left edge was a dashed line of disconnected ticks** — the block's border was drawn only on content rows, so the blank rows between sections carried nothing and the edge read as a column of loose marks running the height of a forty-line post: a rendering artefact rather than a container delimiting anything. The border is now drawn on the separators too, which is what every box-drawing panel has always done. Two related defects fell out of the same investigation. The beacon carried both `padding: 0 1` and `margin: 0 1`, so its rail sat one cell right of every chat block above it and the two read as one broken edge; and every dashboard row was padded out to the terminal edge, so a twelve-character line shipped a ~1400-cell run of styled spaces after it — pure overhead, and a hazard for terminal selection and soft-wrap. The overlay's rows are now their natural width, while the pinned beacon keeps the exact-width invariant its layout tests assert.
- **A paused or blocked goal advertised work that was not happening** — the `▸ current` mark came from `current_task()`, which reports the next pending task regardless of goal status, so a goal paused with `Esc` showed a bold accent "current" row for a task nobody was working on, and a blocked goal looked identical to a running one. Nothing is in flight unless the goal is `active`, so nothing is marked. Separately, the *reason* a goal was blocked or paused lived only in the goal file and the tool snapshot, so a blocked goal and a paused one were indistinguishable on screen; the dashboard now carries a `why` line in the user's own words.
- **The goal beacon froze a live fan-out** — the widget repainted on a fixed five-second interval, so while the very sub-agents it was summarising streamed, thought and switched tools, the row reporting them sat mid-tool for seconds at a time and the beacon could contradict the panel directly below it. The cadence is now half a second while anything is queued or running and five seconds otherwise.
- **The narrow-terminal goal status line overflowed the screen** — the one-line fallback appended a fixed set of segments and only guarded the objective, so a running goal with a plan printed a 37-cell line into a 24-cell terminal and the terminal wrapped it onto a second row under the editor. Cells are now budgeted rather than assumed: the objective gets a reservation first, then each segment is taken in priority order if it still fits, and a segment that does not fit is *skipped* rather than ending the line, so a long token count can no longer hide the short progress figure standing behind it.
- **Queued sub-agents got a row each in the dashboard, and every row was identical** — an agent that has not started can only report `0 turns · 0 tokens · 0.0s`, and two identically-named queued runs rendered as indistinguishable lines, so the list was noise that read as information. Queued agents now collapse to one `○ N queued` line, matching the pinned panel, and finished runs summarise to `✓ N finished · 12.4k`. The same edit removed a whitespace-only row that appeared when nothing had finished: indenting the summary produced `"  "`, which is truthy, so the renderer appended a blank line the beacon then drew as a second gap.
- **The goal beacon reported a plan the reader could misread** — the task window was anchored on the last *completed* task, which could scroll the one row that matters — the active task — off the bottom, and the subtasks of the task in flight were appended after the window instead of hanging off their parent, stranding them under whichever task happened to be last. The window is now centred on the active task, so the one row that cannot be reconstructed from a `+N more` count is always on screen, and subtasks ride with whichever task owns the current focus.
- **The recap ate the sub-agent's result** — a recap is a summary of a *finished* conversation, but the idle timer only checked whether the parent turn was running. A session that had handed its work off to background sub-agents looked idle, so thirty seconds later it spent an LLM call restating what was already on screen, and the summary landed in the chat *instead of* the sub-agent's result reaching the agent. The finding was then visible to the user and invisible to the model — which reads as "the sub-agent finished and the notification never arrived", when the notification had worked all along. Recap is now gated on the session being genuinely idle: sub-agents queued or running suppress it, checked at all three points where it can slip through (arming the timer, the timer firing, and after the LLM call is already in flight). It is deferred rather than dropped, so it returns once the work lands, and an explicit `/recap` still works mid-fan-out because there the user asked for it.
- **A cancelled or failed turn could leave the session permanently "busy"** — `_run_agent` cleared `_is_running` on the normal path only, so a run that raised — or was cancelled when a newer prompt took over the worker group — left the flag set. Every gate in the app reads that one flag: Esc, the status line, the recap timer, and every background wake-up, all of which would have refused to fire for the rest of the session. The flag is now cleared in a `finally`.
- **A finished background sub-agent never reached the agent** — `background: true` dispatched work that took minutes, and the parent turn took seconds, so the sub-agent almost always finished *after* its parent had gone idle. Two gaps in a row swallowed the result: the parent loop only drained completions *between* turns, so an already-settled task was appended to the session but not shown to the model until the turn after next; and nothing started that turn, because a completion had no way to signal an idle session. The sub-agent ran, produced an answer, and the agent then replied as if it had never happened — the failure mode is silence, not an error, so it read as the model ignoring work it had requested. `BackgroundTaskManager` now exposes a settlement listener, the TUI resumes the session on it (with a status line naming the sub-agent, so the turn is not mysterious), and `Agent.run` injects anything already settled *before its first model call* rather than between turns. A completion is still delivered exactly once, and a wake-up turn that dispatches again is capped at four chained resumes before the session stops and says why — a fan-out has to converge.
- **A finished sub-agent row stayed pinned for the rest of the session** — the Agents panel stopped its repaint timer as soon as nothing was running, so the linger window that decides when the strip retires was never re-checked. The last finished row sat above the editor indefinitely, which is the opposite of what a live-status strip should do. The panel now keeps a slow clock alive through the linger window and unpins itself when it closes, verified by a test that fails against the old stop-on-idle behaviour.
- **Sending a message erased every tracked sub-agent** — the sub-agent registry was cleared at the start of each run, on the reasoning that rows should describe the work in flight *now* rather than every sub-agent the session ever dispatched. That is wrong for exactly the sub-agents that matter: a `background: true` dispatch returns immediately and finishes on a later turn, so the user's next message made the panel blink out from under agents still working toward it, and their counters restarted from nothing. The turn boundary now ages out only runs that *ended* more than three minutes ago, so a live or queued agent is never dropped however old its dispatch.
- **A reloaded extension could silently run the previous version** — the extension loader handed each file to `spec.loader.exec_module`, which validates cached bytecode against the source's *mtime and size*. An edit that kept the file the same length — changing a constant, a threshold, a version string — was served from `__pycache__`, so a reload reported success while executing the old code. The same applied a fortiori to a package extension's submodules, which resolve through the normal finder and stayed stale across every reload until the process restarted. The loader now compiles the source it just read, and a reload additionally drops the imported modules and each package's `__pycache__`, so an edited, added, or renamed submodule is actually visible. A failed import also removes the half-built module, so a later reload cannot bind to a broken one.
- **The `ipython` tool was handed to tool-first agents** — `IpythonTool` was registered `is_default=True` unconditionally, so every tool-first session advertised an 11-tool surface (`ask_user, task, web, goal, ipython, read, edit, write, bash, find, skill`) containing a persistent Python kernel that mode never wires up. It was not cosmetic: `ui_block` is mode-gated but `execute` is not, so the model could actually boot a kernel in tool-first mode — with no kernel lifecycle, no compaction bridge, and no cell widget registered to render the output. The default tool set is now mode-aware, which is also what RLM sub-agents resolve their base names from, so `code_first` keeps the kernel for parents and children alike. `ipython` stays registered, so a profile can still opt in by name via `tools_allow` or a tool group.
- **Host-bridge failures all looked the same to the model** — every failure crossing the kernel↔host boundary arrived as a raw Python traceback, so `No tool named 'goal'`, `goal refused: not your session`, and a host-side defect were indistinguishable. The model retried the identical call or blamed its own cell. Failures are now categorized — `unknown_tool`, `invalid_input`, `tool_failure`, `invalid_output`, `host_unavailable`, `timeout`, `execution_failure` — and each category carries a different prescribed next step, since a category that does not change behavior is decoration. Only `timeout` is marked retryable. The design follows opencode's CodeMode, including its public/private split: a model-safe message plus a host-only detail, and sanitization by default so an unclassified host exception contributes at most its type name instead of a path or a value's `repr`. `plain_data` had the same leak — a result whose `__str__` raised propagated that exception raw across the bridge — and now wraps it.
- **`ctrl+t` could kill the app on a supported thinking level** — cycling to a level the catalog advertised but the provider's stale enum did not list raised `ValueError: Invalid thinking level 'max' for openai. Valid levels: ['none', 'minimal', 'low', 'medium', 'high', 'xhigh']` straight out of the Textual action, tearing down the running session (recoverable only via `vtx -r <id>`). Two independent lists decided what was valid — the models.dev-derived picker levels and the provider's own enum — and nothing reconciled them; the provider now shares one enum that includes `max`, `set_thinking_level` clamps instead of raising, and the runtime clamps against the offered set before applying, so no stale or restored value can reach an exception.
- **Auditor verdicts were truncated mid-sentence, causing endless re-audit loops** — the completion auditor's findings were clipped to 1500 characters on write, so a verdict was stored ending at e.g. `**Contract status:** 106 goal-re…`. The executing agent could not read the rest, could not tell the text had been clipped, re-completed the goal, and was failed again on the same finding indefinitely. Verdicts and completion claims are now stored whole; where text must still be shortened for the activity ledger it is cut on a paragraph or word boundary and explicitly marked as clipped. `goal(action="get")` likewise returns the full objective, verification contract and verdict instead of a 200-character summary, so the agent's only view of its own state is no longer silently abridged.
- **`Session.load` discarded every `runtime_checkpoint` entry** — the loader had no branch for that entry type, so a resumed session dropped them silently and every parent chain running through a turn was severed, collapsing `get_branch()` to a handful of entries and breaking `/tree` history for any reloaded session.
- **Undo restored nothing when a turn's edits came from an unreporting tool** — the restore set was derived from `file_changes` on tool results, so edits made through `bash`, `ipython` or a `python` cell were excluded and the UI reported "no file changes" over a still-dirty worktree. The restore set is now the worktree diff recorded when the turn is bracketed.
- **Undo never matched any file in real sessions** — tool results report absolute paths while git tree entries are project-relative, so the two sets could never intersect and every restore was a silent no-op. Both sides are normalized against the project root before comparison.
- **Undo could not see a turn's snapshot** — the worktree is hashed at turn start but the user message is appended from inside the agent loop, so the snapshot always precedes the prompt it belongs to; the lookup scanned the other way and found nothing. Turn records now name the user message they belong to, so association no longer depends on entry order.
- **`/compact` shadowed by the RLM `compact` kernel skill** — command routing checked registered skills before the built-in router, so any skill sharing a name with a built-in silently won. `/compact` and `/refine` were both unreachable; built-in commands now take precedence and the completion list is de-duplicated.
- **YAML folded block scalars mangled skill descriptions** — frontmatter was parsed with a naive key/value scan, so `description: >` was stored as the literal string `>`, destroying the description of 15 bundled skills in both the model-facing skill index and the `/` list. Frontmatter now parses with `yaml.safe_load`, falling back to the old scan.
- **Python skills auto-registered as slash commands** — kernel skills are imported by name inside the REPL, so a `/name` entry is meaningless for them; they now follow the same opt-in rule as every other skill.
- **TUI freeze on chatty tool output** — live tool output re-rendered and re-laid-out once per output delta, so a tool streaming faster than the frame rate saturated Textual's single event loop and the whole app stopped responding, with keystrokes, the spinner and `Esc` all blocked. Renders and scroll-to-bottom now coalesce into one pass per frame, matching the batching the text-streaming path already used; 2000 deltas dropped from ~860ms to ~150ms of event-loop time.
- **RLM host bridge could hang a cell indefinitely** — a `tool.call` dispatched through the kernel bridge awaited the tool inline with no bound, so the cell's own timeout was never reached and the kernel's `done` was never read, leaving the session kernel's execution lock held for every later cell. The dispatch now runs on the cell's remaining budget and always writes a `host_reply`, and the turn's `cancel_event` is forwarded to bridge tools so `Esc` reaches them.
- **IPython cell output could vanish** — output was cleared on a collapsed block and the details class was never removed when re-expanding, so a cell's result could disappear with no way to get it back.
- **Kernel-only skills were offered to agents that cannot run them** — a Python-backed skill (`pyproject.toml` plus `src/<import_name>`) is a module imported into the persistent IPython kernel, and its SKILL.md is a REPL API reference ("call `await compact.run()` from the REPL"). Outside RLM mode there is no `ipython` tool at all, yet all five bundled kernel skills — `edit`, `compact`, `refine`, `agent-message`, `agent-observe` — plus any user-authored Python skill were injected into the mandatory skills catalog and into `skill(action="list")`. That is worse than omitting them: `compact`'s description reads as universally applicable, so the agent loaded the skill, spent context on it, and then had no tool to call. All three discovery surfaces are now mode-aware: the tool-first catalog and skill list omit kernel skills, RLM mode keeps them in the routing index with their import names, and a kernel skill can no longer be registered as a `/command` even by opting in, since `/name` would splice REPL documentation into the user message. The prompt's explanation of the kernel import contract is also omitted when no kernel skill is on offer, instead of describing a capability the agent lacks.
- **The `skill` tool ran a stale fork of the skills loader** — `vtx.coding_agent.context.skills` had diverged into a second, hand-maintained copy with no Python-skill detection, no YAML frontmatter parsing, and `register_cmd` still defaulting to `True`. The tool therefore advertised a different set of skills than the system prompt it is supposed to mirror, and two earlier fixes (opt-in registration, folded-scalar descriptions) never reached it. It is now an alias of the single canonical implementation; the rest of that package was already byte-identical.
- **An optional tool parameter that was explicitly `null` raised a validation error the model could not see or recover from** — the JSON-Schema bridge typed a non-required field as `str` with `default=None`, so passing `null` for an unset optional was rejected even though omitting it was fine. Models routinely send `null` for an unset optional, and with MCP every schema arrives from a third-party server, which turned this from a rare edge into the common case. Non-required fields are now nullable.

### Removed
- **Deprecated OpenJarvis utility modules** — `progress_events`, `prompt_templates`, `restart`, `runtime`, `searchusage` and `tool_hints` were unreferenced and are deleted along with the obsolete realtime-streaming test that covered them; `.gitignore` and the TUI stylesheet lost their corresponding dead entries.


## [1.2.0] - 2026-09-08

### Added
- **RLM mode with persistent IPython REPL** — new `rlm` mode that collapses the agent toolset to a single `ipython` tool backed by a long-lived IPython subprocess; variables, imports, and side effects persist across turns, matching Prime Agent's REPL-first workflow.
- **IPython manager with kernel pool** — `IpythonManager` maintains a pool of persistent IPython kernels keyed by session, enabling parallel subagent execution without restarting the REPL; output streaming uses a newline-delimited JSON protocol.
- **Synchronous thread-based runtime** — `IpythonRuntime` runs cell execution in a thread executor and uses a blocking stdout reader plus Queue, eliminating async reader race conditions and reducing latency compared to the previous async approach.
- **Settings UI toggle for RLM mode** — mode selection moved from a slash command to the Settings panel (`mode: standard | rlm`), streamlining the UI surface.
- **RLM prompt infrastructure** — dedicated `rlm_master_prompt.md`, prompt builder, and system prompt for the restricted-tool RLM runtime.
- **Tool-call RPC bridge** — the REPL can now invoke main-process tools (`web_search`, `goal_*`, `rlm`, etc.) via a `tool_call`/`tool_result` JSON protocol over stdin/stdout, so helper functions actually execute instead of raising `NameError`.

### Changed
- **`python_repl` renamed to `ipython`** across tools, prompts, config, and manager modules to reflect the persistent-kernel model.
- **RLM mode restricts runtime tools** — when `mode=rlm`, the active tool list is reduced to the single `ipython` tool, removing standard coding-agent tools for the duration of the session.
- **Dedicated stdin reader thread** — the runtime now uses a daemon thread + `asyncio.Queue` for stdin instead of `run_in_executor(readline)`, preventing deadlocks when a worker thread blocks waiting for a tool result.

### Fixed
- **Double-execution of trailing expressions** — the runtime now skips the eval block when the expression contains a `Call` or `Yield`, preventing outputs like `print(2+2)` from running twice and breaking tool-call loops.
- **Premature turn ending in RLM mode** — empty-cell synthesis, errored tuple returns, and `mutating=False` on the `IpythonTool` were corrected so the runtime waits for real output instead of ending the turn early.
- **IPython runtime async blocking** — cells now execute in a worker thread, and trailing-expression detection uses `ast.parse` so the asyncio loop stays free and the runtime doesn't hang on blocking calls.
- **`IpythonManager.execute()` keyword argument mismatch** — `tool_executor` is now accepted and forwarded to `IpythonKernel.execute()`, fixing the unexpected-keyword error when REPL helpers dispatch tool calls.
- **REPL helper functions not actually registered** — `web_search`, `goal_get`, `goal_update`, `goal_set_tasks`, `rlm`, and `call_tool` are now injected into the REPL namespace, matching what the RLM system prompt documents.
